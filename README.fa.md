## 🌌 چیه این؟

**Eidolon** یه فریم‌ورک **ماژولار، ریموت‌محور** برای مدیریت و اجرای ماژول‌های امنیتی/اتوماسیونه.
به جای اینکه ده‌تا اسکریپت پراکنده داشته باشی، همه‌چیز یه جا جمعه:

- 🛰️ **Repositories از راه دور** — ماژول‌ها رو از چند ریموت (با اولویت‌بندی) بکش
- 📦 **نصب خودکار** — tar / tar.zst / git clone
- 🧩 **سیستم ماژول** — هر `.py` که `run(opts)` و `OPTIONS` داشته باشه، ماژوله
- 🎛️ **CLI تعاملی** — با autocomplete، prompt زنده، جدول‌های رنگی، session tracking
- 💾 **Persistence** — globals و sessionها توی SQLite ذخیره می‌شن
- 🎨 **خروجی رنگی** — True-color ANSI، بنر گرادیانتی، کاراکترهای یونیکد

## 👻 Wraith — هسته‌ی C2 (هر چیز دیگری ماژول است)

یک **هسته‌ی** C2 مینیمال داخل مخزن — پکیج `wraith/` — که **هیچ‌وقت توسط موتور
اکسپلویت import نمی‌شود** و **صفر سرور، صفر لیسنر و صفر کامپایلر** دارد. هسته فقط
«زبان مشترک و قفسه‌ها» است؛ هر چیزی که واقعا اجرا می‌شود یک ماژول معمولی است که
هرکس می‌نویسد:

- **هسته فقط سه فایل است** — پروتکل JSON روی سیم (`protocol.py`)، رجیستری
  سشنِ thread-safe (`sessions.py` با `default_registry()` سراسری) و انبار
  پی‌لود تایپ‌دار (`store.py`). هیچ کد ترنسپورتی در کار نیست.
- **لیسنرها ماژول‌اند** — ماژولی از نوع `listener` هر ترنسپورتی را که بخواهد
  (WebSocket، TCP خام، HTTP beaconing، هر چه بعدا بیاید) با هر کتابخانه‌ای که
  بخواهد اجرا می‌کند. چیدمان داخلیش کاملا آزاد است؛ فریم‌ورک فقط اسکریپت ورودی
  ماژول را می‌شناسد. سشن‌ها را در رجیستری هسته ثبت می‌کند، پروفایل کاری‌اش را
  منتشر می‌کند (`EIDOLON_SHELL.wraith_listener` → `url` / `token` / `tags`)
  و `stop()` دارد. دستور `gen <module>` آن را به‌عنوان یک job در پس‌زمینه
  مدیریت‌شده بالا می‌آورد.
- **بیلدرها ماژول‌اند، نه کد فریم‌ورک** — مخزن **صفر** سورس پی‌لود و **صفر**
  کامپایلر دارد. بیلدر پی‌لود صرفا ماژولی از نوع `payload` است: سورس‌هایش هر جا
  که نویسنده بخواهد می‌نشیند (`_src/` یا هر چیز دیگر — اصلا قرارداد نیست)،
  اسکریپتش آرتیفکت را به *هر زبانی* که دلش خواست می‌سازد (Go، Nim، C، Rust،
  C#، bash، python، PowerShell، …)، پروفایل لیسنر (URL + token + tags) را هر
  طور که خواست امبد می‌کند و در انبار ثبت می‌کند — اکسپلویت‌ها با نام و با
  فیلتر تایپ برمی‌دارندش.
- **انبار پی‌لود تایپ‌دار** — هر آرتیفکت با تایپ (file-posix / file-win /
  shellcode / cmd / code) و مانیفست با SHA-256
- **قرارداد تگ پروتکل** — لیسنر و پی‌لود باید یک تگ گویای مشترک داشته باشند
  (مثل `ws-json-async`) وگرنه با کد 4403 هرگز به هم وصل نمی‌شوند

```bash
eidolon ❯ gen wraith-ws/listener port=8443
                                         ⬢ job #1 — لیسنر روشن است
eidolon ❯ gen ghost-implant              (ماژول نوع payload — می‌سازد و ثبت می‌کند)
                                         ⬢ stored: ghost-go [file-posix] · ws-json-async
... ماژول اکسپلویت باینری را به هدف می‌رساند ...
  ⬢ payload connected  5f8e12c2 · alice@corp-ws · go/linux-amd64 · 10.4.2.9:51515
eidolon ❯ c2 sessions                   (جدول زنده — ● فعال، ○ گم‌شده)
eidolon ❯ kill 1                        (خاموشی تمیز — ضد انطباق‌شناسی)
```

هر پی‌لودی که زنگ بزند، همان لحظه در کنسول گزارش می‌شود: هویت با مهر زمان،
کاربر هدف، هاست، نوع ایمپلنت و آدرس.

### دستورها

| دستور | کاری می‌کند |
|---|---|
| `gen <ماژول لیسنر> [k=v …]` | لیسنر را بالا می‌آورد — job پس‌زمینه؛ پارامترهای جاافتاده پرسیده می‌شوند، مقدار فلگ مقدم است |
| `gen <ماژول پی‌لود> [k=v …]` | پی‌لود می‌سازد و ثبت می‌کند (پروفایل لیسنر امبد شده، تگ مهر شده) |
| `jobs` | کارهای پس‌زمینه — id · وضعیت · عمر |
| `kill <id>` | خاموشی تمیز از طریق `stop()` خود ماژول (موقع `exit` هم خودکار) |
| `run --bg` | هر ماژولی را پس‌زمینه می‌کند (ماژول‌های لیسنری همیشه job می‌شوند) |
| `c2 status` | پروفایل لیسنر، تگ‌ها، تعداد jobها و سشن‌ها |
| `c2 sessions` | جدول زنده‌ی سشن‌ها (فعال / گم‌شده) |
| `c2 payloads` | انبار تایپ‌دار پی‌لود (name · type · protocol · backend · sha256) |

دستور `c2` فقط خواندنی است — `serve` و `build` و `stop` حذف شده‌اند؛ جای‌شان
`gen` و `jobs` و `kill` است.

### دست‌دادن تگ پروتکل

هر لیسنر گویه‌های سیمِ خودش را اعلام می‌کند؛ هر پی‌لود هم گویه‌هایی که
می‌فهمد. **فقط روی تگ مشترک وصل می‌شوند** — وگرنه دست‌دادن با کد 4403 می‌میرد
(و پی‌لودی که روی گویه‌ی دیگر ثبت شده باشد هرگز در فیلتر تایپ اکسپلویت پیدا
نمی‌شود — جفت‌شدن اشتباه تصادفا ممکن نیست):

```
  listener: tags = {ws-json-async}          (اپشن ماژول لیسنر — هر تعداد)
  payload : tags = {ws-json-async}          (موقع ساخت امبد می‌شود)
  → connect only on ws-json-async ∩ tags ≠ ∅
```

در عمل یکی، حداکثر دو تا — ولی فضای قابلیت نامحدود است، پس یک گویه‌ی جدید
(`ws-framed-binary`، …) می‌تواند روی همین دستگاه بی‌هیچ اتصال‌اشتباهی با
قلم قدیمی همزیستی کند. اندیس‌های ریموت هم می‌توانند با فیلدهای اختیاری
`"protocol"` / `"payload_type"` گویه‌ی ماژول منتشرشده را سنجاق کنند.

### معماری — سه فایل کوچک، یک پوشه، صفر سرور

```
wraith/
  protocol.py   قرارداد سیم — مشخصه‌ی فریم، سقف‌ها، واژگان تگ
  sessions.py   رجیستری سشن thread-safe (+ default_registry() مشترک)
  store.py      انبار تایپ‌دار پی‌لود + resolve_payload() دروازه‌ی تایپ
```

لیسنرها و بیلدرها کنار ماژول‌ها زندگی می‌کنند (`~/.eidolon/modules/هرجا/`) —
بیرون از فریم‌ورک، دقیقا هر جا که نویسنده‌شان بخواهد، با چیدمان داخلی
کاملا آزاد (فریم‌ورک فقط اسکریپت ورودی ماژول را می‌شناسد).

خود فریم‌ورک حالا **صفر وابستگی C2** دارد — ماژول لیسنر WebSocket سادگی
`websockets>=11` را در `REQUIREMENTS` خودش اعلام می‌کند (`deps` نمایشش
می‌دهد، هرگز خودش نصب نمی‌کند)؛ گواهی TLS هم کار ماژول است. فایل‌های
آپلود/دانلود روی تکه‌های base64 ِ۲۵۶ کیلوبایتی جریان دارند (سقف ۱۰ مگابایت)؛
فریم‌ها سقف ۱ مگابایت؛ argv پاک‌سازی می‌شود (≤۱۲۸ × ۴KB)؛ خروجی‌ها در
۵۱۲ کیلوبایت کلمپ می‌شوند. سشن‌ها روی قطع شدن `lost` می‌شوند و هرگز
لیسنر را نمی‌اندازند.
